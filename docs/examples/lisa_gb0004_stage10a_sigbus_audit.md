# Stage-10A SIGBUS read-only audit

Audit date: 2026-10-08. **Causal classification: A — INFRASTRUCTURE / FILESYSTEM FAILURE (hardware memory corruption).** The original experiment remains officially **CASE D — RECONSTRUCTION / NUMERICAL FAILURE** under its preregistered abnormal-process-termination criterion. These classifications answer different questions. No sampling, model evaluation, retry, code change, budget change, or methodological change was performed in this audit.

All 150 preregistered protected source/configuration hashes also matched. The failed artifacts and historical reports were not edited.

The frozen design SHA256 remains `92dae65a1e86255fbb73cef634307350ced2750fbe1c24f3590a6cbe061522bc`; runner SHA256 remains `88737da6a019b1bfe57d85f0f5ef90fb94dda1bc5dc84e8dec403cc47f9cc6a5`. `failure.json` is a retrospective abnormal-exit receipt, not a Python exception or traceback captured at the fault. It records signal 7 and shell exit 135. The stdout/stderr log contains progress and no Python exception.

At 08:06:09 UTC the same host also recorded corrected ECC errors, identifying `P2-DIMMC1`, socket 1 / memory controller 0 / channel 2 / DIMM 0. Earlier uncorrected errors and a later recoverable hardware event appear in the buffer. The crash-time uncorrected error and process kill, rather than nearby corrected events alone, establish the causal finding. The exact defective physical component is not independently diagnosed here.

A readable original system core exists at:

`/var/lib/systemd/coredump/core.python.11062.bbe46f351d1343d28f4da68339d10bee.28874.1791446885000000.lz4`

Its SHA256 is `f9cfc1aa88babd1a7fbba2a446707edf63a4e27f52dd45551729200c89826497`, compressed size 67,945,657 bytes. Extended attributes identify UID 11062, host `som5.ific.uv.es`, host PID 28874, signal 7, timestamp 1791446885 (08:08:05 UTC), executable `/r5/home/rruiz/software/miniconda3/envs/blackjax-ns/bin/python3.11`, and core limit 314,572,800 bytes.

Read-only examination of a decompressed derivative confirms:


The installed Linux header `/usr/include/asm-generic/siginfo.h` defines code 4 as `BUS_MCEERR_AR`: hardware memory error requiring action. The core contains namespace-local LWP 3, consistent with saved process PID 3; its command, executable, UID, timestamps and host PID resolve the association with Stage 10A. Kernel messages and the core differ by approximately one second; neither implies a precise Python instruction timestamp.

The core is truncated at the recorded 300 MiB core limit (GDB expects at least 4,630,016,000 bytes). GDB warns about truncation, executable matching and unreadable shared-library list entries. It cannot unwind the faulting stack beyond the unknown top address. No named JAX/XLA/HDF5/BLAS frame can be established. The hardware signal information and command identification remain readable. A fault occurring in native execution does not make this a native-library software defect.

The original compressed core was left untouched. Derived core, GDB output and a kernel excerpt are separately stored under `/tmp/lisa-gb0004-stage10a-sigbus-audit`; these are audit derivatives, outside the immutable failed-run directory and outside git. The decompressor used the installed `liblz4.so.1`; no software was installed or changed.

`coredumpctl`, system/kernel journal queries and user journal queries could not open journal files without additional permissions; `coredumpctl` also reported a denied bus connection. `/var/log/messages` is not user-readable. No privileged access was requested. Direct core-file access and `dmesg` nevertheless supplied decisive evidence.

## Filesystem and runner inspection

The Stage-10A observer creates **15** `numpy.lib.format.open_memmap` `.npy` files per level, with `mode="w+"`, fixed full-run shapes and separate per-level paths. Writes copy NumPy views of returned JAX values into these mapped files. All inspected L1 files have the expected full payload plus 128-byte NPY header; no shortened file was observed. L0 mappings also remain visible in the core's file-mapping table. This retention increases mapping lifetime, but inspection identifies no deterministic truncation, replacement, premature unmapping or dangling host-buffer defect. Arrays are retained by the observer closures during use.

No concurrent writer or restart child was active: sampling is sequential and the restart subprocess launch occurs only after primary reconstruction sets complete. There is no runner unlink/replace of live mapped files. `load_history` copies arrays from a context-managed NPZ. The likelihood's HDF5 loaders materialize arrays with dataset reads and float64 copies while read-only handles are open; the likelihood closure stores JAX arrays. No lazy dataset reference, HDF5 mmap path or ongoing HDF5 write was identified. No deterministic runner defect was established.

## Decision and rerun boundary

Exactly one causal class applies: **A — INFRASTRUCTURE / FILESYSTEM FAILURE**, specifically external hardware memory corruption. Classes B–E are not established. The unknown native instruction and truncated backtrace do not require an inconclusive causal classification because the core signal code and matching kernel kill supply direct external-failure evidence.

No numerical/cache invariant was recorded as failing before the crash. L0's complete saved-state audit passed; L1's last recorded validated exchange passed. This does not certify unobserved operations or statistical convergence, and hardware-corrupted execution cannot supply completed inference.

**Exactly one clean rerun is scientifically justified under the user's external-failure exception**, with the frozen design, budgets, methodology and fresh-history requirements preserved, on a host whose hardware fault has been addressed or an unaffected host. This is a scientific justification, not execution authorization in this read-only audit. No rerun occurred. No budget adaptation, posterior-driven change or repeated trial-and-error execution is justified.

No further evidence is needed to establish the external causal class. The missing complete stack would refine the exact consuming operation; confirmation of repaired/unaffected execution infrastructure is needed before a future clean run. The immutable original Stage-10A CASE D result is not retroactively changed, and no evidence or posterior inference becomes valid from this audit alone.
